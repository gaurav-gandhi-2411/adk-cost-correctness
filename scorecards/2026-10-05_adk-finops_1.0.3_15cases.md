## What changed vs the 0.6.3 scorecard (5 PASS / 5 INCOMPLETE / 5 FAIL)

**Nothing.** All 15 verdicts are identical to 0.6.3 even though 9 releases shipped in between
(0.6.4, 0.6.5, 0.7.0, 0.8.0, 0.9.0, 1.0.0, 1.0.1, 1.0.2, 1.0.3, 2026-09-23 to 2026-10-03: remote rate-card sync, budget guards, `@billable` tool
billing, a report CLI, a security pass, latency metrics). None of that touches a graded case.

- **C1_unknown_model and M2_claude_opus_5 still FAIL.** The model is still priced at the fallback rate
  ($0.5500000 for both). 1.0.3 logs a warning when it does so (shown above), and its per-call log line carries a
  `FALLBACK RATE` marker (`adk_finops/plugin.py:683`; whether that line is printed in this suite's run was not
  observed, it is not in the captured output). `docs/SCORING.md` fails ANY reported figure for a genuinely
  unpriceable model, flagged or not, so the verdict follows the rule. See the maintainer's position below.
- **C4_double_registration still FAILs** ($0.0016000 against $0.0008000, 2.00x): the callback still fires
  twice. See the maintainer's position below.
- **G3r and A1 still FAIL** and were never reported upstream.
- **Remote rate-card sync** (added in 0.6.4) is off by default (`sync_remote_rates: bool = False`,
  `adk_finops/plugin.py:104`), and this suite runs offline, so these results are the default install's. Whether
  turning sync on changes C1 or M2 was not tested.

## The maintainer considers C1 and C4 intended behavior

Quoted verbatim from `dmoonat` (owner of adk-finops), who closed both issues:

- Issue #1 (C1, unknown model priced at the fallback rate), 2026-09-23T04:04:00Z: "We are not doing a pre-check
  whether model pricing is available or not, and output will reflect the tokens so user can calculate with the
  available price or better way is to register it with the package as mentioned
  [here](https://github.com/dmoonat/adk-finops/issues/1#issuecomment-5762512435)."
- Issue #2 (C4, double registration), 2026-09-21T15:08:07Z: "This behavior is expected as adk-finops is a adk
  plugin." and, 2026-09-23T04:06:39Z: "Expected behavior, please check above
  [comment](https://github.com/dmoonat/adk-finops/issues/2#issuecomment-5762741336), thanks".

So C1, C4 (and M2, which is the same mechanism as C1) are **disputed scoring rules, not settled defects**: this
suite's rule says a cost tool must not report a dollar figure for a model with no published price and must not
silently double-count a doubly registered plugin; the adk-finops maintainer's position is that both are
documented, expected behavior. Issue #3 (C5, streaming) was fixed (commit `38cbad874a420f4a41ba56efd740e1d143aa6e1f`, 2026-09-21).
